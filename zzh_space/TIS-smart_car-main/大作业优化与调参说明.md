# 大作业优化与调参说明

本文档说明本轮针对 TIS 实车方案新增和调整的功能，重点服务现场快速落地、低速验证和参数调试。

主要配置文件：

`TIS-smart_car-main/line_follow_ws/src/line_follower/config/line_follower_params.yaml`

主要代码位置：

- `line_follower_node.cpp`：line follower node（巡线主节点），负责白线巡线、黄线停车、红色避障、终点停车。
- `detection_turn_controller.cpp`：detection turn controller（检测转向控制器），负责根据 YOLO 检测结果发布 `/cmd_vel_detection`。
- `ros_yolo_detect_v8.py`：ROS YOLOv8 detector（ROS2 数字检测节点），负责数字识别并发布 `/hobot_dnn_detection`。
- `start_final.sh`：final startup script（一键启动脚本），现在会把同一个参数文件传给 YOLO 节点。

## 1. 黄线停车可靠性优化

### 数据流

相机图像 `/camera/color/image_raw`
-> `line_follower_node`
-> HSV 黄色检测
-> 黄线接近减速或停车确认
-> `/cmd_vel_stop`
-> `cmd_mux_node`
-> `/cmd_vel`
-> 底盘停车

### 本轮实现

- 新增 `yellow_area_ratio`（黄色面积占比），用于判断黄线远近和置信程度。
- 新增黄线接近减速：黄色刚进入 ROI（感兴趣区域）时先降速。
- 新增连续帧确认：连续多帧达到停车阈值才停车，降低单帧误检。
- 新增黄线离开判定：黄色面积降到较低阈值后，才允许下一条黄线重新触发。
- 将旧版 `yellow_permanent_count` 默认设为 `0`，避免终点停车模块未开启时意外永久停车。

### 相关参数

参数路径：`line_follower_node.ros__parameters`

| 参数 | 作用 | 调试建议 |
| --- | --- | --- |
| `use_yellow_filter` | 是否启用黄线检测 | 一般保持 `true` |
| `yellow_h_low` / `yellow_h_high` | 黄色 Hue（色调）范围 | 现场黄色偏橙或偏绿时调整 |
| `yellow_s_min` | 黄色最小 Saturation（饱和度） | 误检浅色区域时提高 |
| `yellow_v_min` | 黄色最小 Value（亮度） | 暗光漏检时降低 |
| `yellow_area_ratio_threshold` | 正式停车的黄色面积阈值 | 停不住就降低，误停就提高 |
| `yellow_approach_enabled` | 是否启用接近减速 | 推荐保持 `true` |
| `yellow_approach_area_ratio_threshold` | 接近减速阈值 | 过早减速就提高，发现太晚就降低 |
| `yellow_approach_speed` | 接近黄线时速度上限 | 冲线就降低，太慢就提高 |
| `yellow_stop_confirm_frames` | 停车确认帧数 | 误停就提高，反应慢就降低 |
| `yellow_clear_area_ratio_threshold` | 黄线离开阈值 | 停车后反复触发就提高或降低需结合 debug 图判断 |
| `yellow_stop_duration` | 每次黄线停车时间 | 停不够就提高，停太久就降低 |
| `yellow_detection_cooldown` | 黄线计数冷却时间 | 同一条线重复计数就提高 |
| `yellow_permanent_count` | 旧版第 N 次黄线永久停车 | 默认 `0`，建议不用它做终点停车 |

### 常见现象

| 现象 | 优先调整 |
| --- | --- |
| 黄线前冲过去 | 降低 `yellow_area_ratio_threshold`，降低 `yellow_approach_speed` |
| 黄线还很远就明显减速 | 提高 `yellow_approach_area_ratio_threshold` |
| 偶尔看到黄色噪声就停车 | 提高 `yellow_stop_confirm_frames` 或 `yellow_area_ratio_threshold` |
| 同一条黄线被计数多次 | 提高 `yellow_detection_cooldown`，检查 `yellow_clear_area_ratio_threshold` |
| 暗光下黄线漏检 | 降低 `yellow_v_min`，必要时降低 `yellow_s_min` |

## 2. 红色区域避障优化

### 数据流

相机图像 `/camera/color/image_raw`
-> `line_follower_node`
-> HSV 红色检测
-> 判断红色区域在线的左侧或右侧
-> 生成短时避障速度
-> `/cmd_vel_follower`
-> `cmd_mux_node`
-> `/cmd_vel`

### 本轮实现

- 不区分红色锥桶和红色禁行区，只要红色区域达到阈值就触发避让。
- 使用“车底部中心 -> 巡线质心”的方向线判断红色区域左右。
- 红色在线左侧时向右转，红色在线右侧时向左转。
- 新增红色最小轮廓面积过滤，减少小红点和反光误触发。
- 新增避障冷却时间，减少连续左右抖动。
- 红色避障不会覆盖 `/cmd_vel_stop`，停车仍然最高优先级。

### 相关参数

参数路径：`line_follower_node.ros__parameters`

| 参数 | 作用 | 调试建议 |
| --- | --- | --- |
| `enable_red_filter` | 是否启用红色避障 | 本轮默认 `true` |
| `red_h_low_1` / `red_h_high_1` | 红色第一段 Hue 范围 | 红色跨 0 度，通常覆盖 0 附近 |
| `red_h_low_2` / `red_h_high_2` | 红色第二段 Hue 范围 | 通常覆盖 160 到 180 |
| `red_s_min` | 红色最小 Saturation（饱和度） | 误检低饱和背景时提高 |
| `red_v_min` | 红色最小 Value（亮度） | 暗光漏检时降低 |
| `red_area_ratio_threshold` | 红色面积比例阈值 | 看到红不避让就降低，误触发就提高 |
| `red_min_contour_area` | 红色最小轮廓面积 | 小噪声误触发就提高 |
| `red_vote_frames` | 红色连续确认帧数 | 误触发就提高，反应慢就降低 |
| `red_turn_yaw` | 避障角速度 | 转不够就提高，太猛就降低 |
| `red_turn_linear` | 避障线速度 | 避障不充分可降低 |
| `red_turn_duration` | 避障持续时间 | 转不够就提高，转过头就降低 |
| `red_cooldown` | 避障冷却时间 | 左右抖动就提高 |
| `red_divider_angle_deg` | 左右分界线角度补偿 | 避障方向判断偏差时微调 |
| `red_debug_overlay` | 是否显示红色避障调试叠加 | 推荐调试时保持 `true` |

### 常见现象

| 现象 | 优先调整 |
| --- | --- |
| 红色在画面里但不避让 | 降低 `red_area_ratio_threshold` 或 `red_min_contour_area` |
| 小红点、反光导致误避让 | 提高 `red_min_contour_area`、`red_area_ratio_threshold` 或 `red_vote_frames` |
| 红在左却向左转 | 检查底盘 `angular.z` 正负方向，必要时调整代码中的避障方向符号 |
| 避障太猛 | 降低 `red_turn_yaw` 或 `red_turn_duration` |
| 避障不够 | 提高 `red_turn_yaw` 或 `red_turn_duration`，适当降低 `red_turn_linear` |
| 连续左右抖动 | 提高 `red_cooldown` 或 `red_vote_frames` |

## 3. 数字识别稳定性优化

### 数据流

相机图像 `/camera/color/image_raw`
-> `ros_yolo_detector`
-> `/hobot_dnn_detection`
-> `detection_turn_controller`
-> `/cmd_vel_detection`
-> `cmd_mux_node`
-> `/cmd_vel`

### 本轮实现

- `ros_yolo_detect_v8.py` 中原本硬编码的模型路径、置信度、跳帧等参数改为 ROS2 parameter（ROS2 参数）。
- `start_final.sh` 启动 YOLO 时会传入同一个 `line_follower_params.yaml`。
- `detection_turn_controller` 修复巡线质心被二次归一化的问题。
- 新增数字类别投票，减少单帧误检触发转向。
- 当前仍不把“稳定踩到数字”作为主要目标，优先保证巡线、停车、避障稳定。

### YOLO 参数

参数路径：`ros_yolo_detector.ros__parameters`

| 参数 | 作用 | 调试建议 |
| --- | --- | --- |
| `model_path` | YOLOv8 权重文件路径 | 路径错误会导致节点无法加载模型 |
| `image_topic` | YOLO 输入图像话题 | 应和相机图像一致 |
| `detection_topic` | YOLO 输出检测话题 | 应和 `detection_turn_controller.detection_topic` 一致 |
| `conf_threshold` | YOLO 置信度阈值 | 漏检就降低，误检就提高 |
| `iou_threshold` | NMS（非极大值抑制）阈值 | 通常保持默认 |
| `skip_frames` | 跳帧数量 | 延迟高就降低，算力不够就提高 |
| `target_digits` | 允许发布的数字类别 | 模型类别名变了时需要同步 |
| `publish_placeholder` | 是否发布空检测占位 | 为兼容现有控制器，默认 `true` |

### 检测转向参数

参数路径：`detection_turn_controller.ros__parameters`

| 参数 | 作用 | 调试建议 |
| --- | --- | --- |
| `confidence_threshold` | 控制器侧置信度阈值 | YOLO 有框但控制器不响应时检查 |
| `frame_window` | 检测会话窗口帧数 | 误触发就提高，反应慢就降低 |
| `class_vote_window` | 类别投票窗口 | 一般与 `frame_window` 接近 |
| `same_class_required` | 同类数字确认次数 | 误检多就提高，漏触发就降低 |
| `y_align_tolerance` | 检测框与巡线质心纵向对齐容差 | 检测到但不触发时可提高 |
| `centroid_timeout` | 巡线质心超时时间 | 巡线质心发布不稳定时可提高 |
| `turn_direction_sign` | 检测转向方向符号 | 检测转向反了就改正负号 |
| `yaw_gain` | 检测转向增益 | 转向不够就提高，太猛就降低 |
| `turn_duration` | 检测转向持续时间 | 转向不够就提高 |
| `turn_linear` | 检测转向线速度 | 转向时冲太快就降低 |

## 4. 终点停车模块

### 当前状态

终点停车代码已经加入，但默认关闭：

`enable_finish_stop: false`

这样当前实车测试不会被未知终点结构影响。

### 数据流

相机图像 `/camera/color/image_raw`
-> `line_follower_node`
-> 黄线计数或终点条件判断
-> `/cmd_vel_stop`
-> `cmd_mux_node`
-> `/cmd_vel`
-> 底盘停车

### 相关参数

参数路径：`line_follower_node.ros__parameters`

| 参数 | 作用 | 调试建议 |
| --- | --- | --- |
| `enable_finish_stop` | 是否启用终点停车 | 现场确认终点结构后再改为 `true` |
| `finish_stop_mode` | 终点停车模式 | 当前支持 `yellow_count` |
| `finish_stop_yellow_count` | 第 N 次黄线触发终点停车 | 确认终点是第几条停车线后设置 |
| `finish_stop_area_ratio_threshold` | 终点黄色面积阈值 | 终点线更宽时可适当提高 |
| `finish_stop_confirm_frames` | 终点确认帧数 | 误停就提高 |
| `finish_stop_hold_forever` | 是否永久保持终点停车 | 比赛终点建议保持 `true` |

### 启用示例

如果现场确认终点是第 4 次黄线，并希望停车后保持不动：

```yaml
enable_finish_stop: true
finish_stop_mode: "yellow_count"
finish_stop_yellow_count: 4
finish_stop_hold_forever: true
```

## 5. 推荐验证顺序

1. 只验证基础巡线和黄线停车：先确认白线稳定、黄线能减速并停住。
2. 开启调试图像：查看黄色面积、红色质心、左右分界线是否符合直觉。
3. 验证红色避障：分别把红色目标放在线左侧和右侧，低速确认避让方向。
4. 查看 YOLO 识别：确认 `/hobot_dnn_detection` 有数字检测输出，不要求立刻踩中数字。
5. 最后再启用终点停车：确认终点结构和黄线序号后再打开 `enable_finish_stop`。

## 7. 本轮未改内容

- 不做复杂路口路径选择，保持现有巡线逻辑。
- 不做速度策略优化，仍以稳定停车和避障优先。
- 红色目标暂不区分锥桶和红色禁行区。
- 终点停车默认不开启，等待现场确认后再调参。
